# 2026-09-15

## FSKit 逆地理编码适配 iOS 26

**改动文件**：`FSKit/Classes/FSLocation/FSLocationManager.swift`

- `address(with:completionHandler:)` 对外签名保持不变（仍返回 `[CLPlacemark]?`），内部按 `#available(iOS 26.0, *)` 分流。
- iOS 26+ 走 MapKit `MKReverseGeocodingRequest(location:)` → `try await request.mapItems`（async 属性，ObjC 侧 completion handler 带 `NS_SWIFT_UI_ACTOR`，所以包在 `Task { @MainActor in }` 里，回调仍在主线程）。
- iOS < 26 保留 `CLGeocoder`。
- 新增 `import MapKit`。

### 关键技术结论（跨项目通用）

1. **警告触发条件**：`com.fuhope.jinzha/swift/Podfile` 的 post_install 把所有 Pod 的 `IPHONEOS_DEPLOYMENT_TARGET` 强制改成 `26.0`，所以 FSKit 源码按 iOS 26 部署目标编译 → `CLGeocoder` 等报废弃告警。Swift 的废弃告警取决于「上下文可用性」，即部署目标或 `#available` 分支；`@available(iOS 26.0, *)` 内部等同部署目标 26。
2. **部署目标 ≥ 废弃版本时，无法屏蔽废弃告警**（实测确认）。只有两个例外：把引用点放进 `@available(iOS, deprecated: 26.0)` 标注的声明内；或放进 `#available(iOS 26.0, *)` 的 **else 分支**（可用性 < 26）。因此在 iOS 26 分支里引用 26 废弃 API 必然报警告 —— 这也是本库用运行时取值桥接的原因。
3. **复用的收敛写法**：
   - 旧 API 路径：包一层 `@available(iOS, deprecated: 26.0, message: "...")` 的 private 方法，只在 else 分支调用 → 库内 + 调用方都不报警告。
   - 必须返回旧类型时：用 `NSSelectorFromString` + `responds(to:)` + `value(forKey:)` 运行时取值，绕开编译期弃用检查。
4. **iOS 26 废弃范围比预期大**：`CLGeocoder`、`MKMapItem.placemark`、`MKPlacemark` 类均已废弃（提示用 `location` / `address` / `addressRepresentations`）；`CLPlacemark` 类及其 `name/locality/subLocality/thoroughfare` 等字段仍是 `API_TO_BE_DEPRECATED`，暂不报警告。替代品 `MKAddressRepresentations` **拿不到 subLocality/subAdministrativeArea**（只有 `cityName` / `cityWithContext` / `regionName` / `regionCode`），所以改用 MapKit 原生结果会影响中文地址拼接质量。
