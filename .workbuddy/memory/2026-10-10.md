### 全量扫描结论
- FSKit 全仓库（排除 .git）**只有 1 处 @objc**：`FSKit/Classes/FSLocation/FSLocationSupport.swift:30`
  `@objc(marsCoordinateFromLocation:)  public static func marsCoordinate(from location: CLLocation)`
  —— 是原 Obj-C 版翻译到 Swift 时留下的显式 selector 兼容，非 UI target-action。
- 无 `addTarget` / `#selector` / `@IBAction` / `@objcMembers` / `@objc dynamic`；无 NSObject/UI 子类带下标式的 selector 调用。
- 隐含 @objc 点也核查过，均无需求：`FSPageReturnHighlight` 用闭包式 `addObserver(forName:object:queue:using:)`（免 @objc）；`FSLocationManager` 的 `NSSelectorFromString("placemark")` 是运行时私有 API 选择器，与自有方法无关；无 `Timer(target:selector:)`、无 KVO observe。
- 调用方核查：FSKit 内部仅自调用重载；消费方仓库（FSJZBussiness / FSJZKit / FSAccountPrivate / FSToDoPrivate / FSUIKit / FSOSS / Tututu）**零引用** `marsCoordinateFromLocation` / `marsCoordinate(`；FSKit 的 Obj-C Example 也未引用 FSLocationSupport。
- ⇒ 结论：该 @objc **可以安全去掉**（删第 30 行属性即可，Swift 调用方不受影响）。唯一残余风险是工作区外的 Obj-C 消费者，概率极低。
