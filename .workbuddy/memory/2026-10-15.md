# 2026-10-15

## FSKit 富文本接口重写：attributedString → FSText（段数组 + Swift 原生 AttributedString）

**起因**：F 问 `FSKit.attributedString` 的 `color: UIColor` 能否改成 `Color`，并觉得这个方法不优雅。

**结论/决策**：
- 颜色**不替换而是抽象**：新增 `FSTextColorConvertible` 协议（`fs_color: UIColor`），
  `UIColor` 与 SwiftUI `Color` 各自 conform，接口参数写 `(any FSTextColorConvertible)?`，
  两种都能直接传，且不产生重载歧义（代价：颜色字面量 `.red` 无法推断类型，须写 `UIColor.red`/`Color.red`）。
- 数据模型换成**段数组**：`FSTextSegment { text, color, font, strikethrough, underline }`，
  按数组顺序拼接；关键词高亮走 `FSTextRule { keyword, color, font, allMatches }`。
- 实现改为 **Foundation 的 `AttributedString`** 逐段 append，最后一次桥接 `NSAttributedString(...)`，
  不再 `NSMutableAttributedString` 逐条 `addAttribute`。属性写入用显式 scope 下标
  （`piece[AttributeScopes.UIKitAttributes.FontAttribute.self] = font`），
  避开同文件同时 import UIKit + SwiftUI 时 `font` / `foregroundColor` 的同名歧义。
- 新入口：`FSKit.attributed(_ segments:)`、`FSKit.richString(_ segments:)`（SwiftUI 用）、
  `FSKit.attributed(_:font:color:rules:)`、`FSKit.richString(_:font:color:rules:)`、
  `FSKit.strikethrough(_:font:color:)`、`FSKit.underline(_:font:color:)`。
- 旧签名全部保留为 `@available(*, deprecated)` 兼容层（在 FSText.swift 末尾，标注"可整段删除"），
  保证 FSJZBus 不炸；其中 `middleLine`/`underLine` 已改静态，旧实例调用走 deprecated 垫片。
  兼容层里 `allMatches: false` 是刻意保留旧"只匹配第一处"行为。

**顺手修掉的问题**：
1. `sourceString.range(of:)` 只返回第一处 → 新实现循环推进 searchRange，默认全匹配。
2. 越界 NSRange 直接 `NSRangeException` 崩溃（Swift 拦不住）→ 统一 clamp 到 `0..<length`。
3. `middleLine`/`underLine` 是实例方法（要 `FSKit()`）且不带 font/color → 改静态并支持样式。

**文件**：
- 新增 `FSKit/Classes/FSText.swift`（286 行）
- `FSKit/Classes/FSKit.swift` 814–817 行的旧实现删除，留指针注释（文件 1269 → 1233 行）
